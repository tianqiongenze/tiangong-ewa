# 002 · 安全运行时与人工确认（Feature Spec）

| 项 | 内容 |
|---|---|
| Spec ID | SPEC-002 |
| 关联需求 | FR-201 ~ FR-204、FR-401 ~ FR-405 |
| 优先级 | P0（一票否决级） |
| 状态 | Implemented |
| 负责人 | 平台 + 安全 |

---

## 1. 为什么（Why）

具身智能与软件智能体的根本差异：**动作有物理后果**。
本 spec 把"安全"从文档条款变成**可执行的代码与可验收的测试**。

## 2. 用户故事

| # | 角色 | 故事 | 价值 |
|---|---|---|---|
| US-1 | 安全专员 | 我想圈定禁入区，机器人物理上进不去 | 红线 R1 |
| US-2 | 维修班长 | 我想审批后才允许危险动作执行 | 红线 R2 |
| US-3 | 安全专员 | 我想有人靠近时机器人立刻停 | 红线 R4 |
| US-4 | 设备科长 | 我想随时一键急停任一台机器人 | 应急 |

## 3. 功能需求（EARS）

| ID | 需求 |
|---|---|
| FR-002-01 | [Ubiquitous] 系统应在每个动作下发前执行电子围栏检查（禁入/停止/限速）。 |
| FR-002-02 | [Unwanted] 若目标位于禁入区，系统应拒绝执行并中止任务，记录 R1。 |
| FR-002-03 | [Event] 当载荷 >50kg 或动作类型属危险类时，系统应要求人工确认令牌。 |
| FR-002-04 | [Unwanted] 若人工确认令牌缺失，系统应拒绝执行并记录 R2；令牌不得由模型生成。 |
| FR-002-05 | [Event] 当停止区检测到人员时，系统应下发停机并在人工确认后恢复。 |
| FR-002-06 | [Event] 当安全专员触发急停时，系统应抢占该机器人执行队列。 |
| FR-002-07 | [Ubiquitous] 系统应将安全裁定（允许/拒绝/停机）与红线编号写入证据链。 |
| FR-002-08 | [State] 当 LLM 规划器不可用时，围栏/停机/急停必须仍然生效（脊髓独立）。 |

## 4. 非功能需求

| ID | 需求 | 目标 |
|---|---|---|
| NFR-002-01 | 安全审查开销 | P95 ≤ 5 ms |
| NFR-002-02 | 停机指令时延 | ≤ 100 ms（遥测轮询周期内） |
| NFR-002-03 | 红线违规留痕率 | 100% |
