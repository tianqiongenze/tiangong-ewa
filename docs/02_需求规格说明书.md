## 1. 范围

本文档规定天工平台的**功能与非功能需求**。每条需求有 ID、有 EARS 句型、有验收标准、有测试映射（宪法第一条）。

---

## 2. 角色

| 角色 | 说明 |
|---|---|
| 设备工程师 | 下单（搬运/巡检/上下料）、看结果 |
| 维修班长 | 审批、接单、遥操作接管 |
| 设备科长 | 红线审批、技能审批、看板 |
| 安全专员 | 安全区管理、事故复盘 |
| 系统集成商 | MES/EAM 适配、机器人 adapter |

## 3. 功能需求（EARS）

### 3.1 作业单与任务分解（FR-1xx）

| ID | 需求 |
|---|---|
| FR-101 | [Event] 当用户提交作业单时，系统应将其分解为**有向无环**任务图（PICK→TRANSPORT→PLACE 等） |
| FR-102 | [Event] 当分解结果存在环或依赖缺失时，系统应**拒绝该计划**并说明原因 |
| FR-103 | [State] 当作业单类型为巡检时，系统应按途经点生成串行 SCAN 链，并在需要时追加 PHOTO |
| FR-104 | [Ubiquitous] 系统应在每个任务上携带物料属性（重量/品类）与目标坐标，供安全审查与能力匹配 |
| FR-105 | [Unwanted] 若 LLM 规划器不可用，系统应降级到规则规划器并显式标记 `planner=rule_fallback` |

### 3.2 审批与人工确认（FR-2xx）

| ID | 需求 |
|---|---|
| FR-201 | [State] 任务在 PENDING 状态时，系统**不得**调度或执行 |
| FR-202 | [Event] 当审批人批准作业单时，系统应将全部任务迁移为 APPROVED 并记录审批人 |
| FR-203 | [Event] 当任务涉及 >50kg 载荷或危险动作时，系统应要求**人工确认令牌**（由人签发） |
| FR-204 | [Unwanted] 若人工确认令牌缺失或由模型生成，系统应拒绝执行并记红线违规 |

### 3.3 机群调度（FR-3xx）

| ID | 需求 |
|---|---|
| FR-301 | [Event] 当任务就绪时，系统应按能力硬门槛筛选机器人（负载/展幅/传感器/技能/电量） |
| FR-302 | [Ubiquitous] 系统应为每个调度决策返回**可解释理由**（含被淘汰者的淘汰原因） |
| FR-303 | [State] 当一台机器人已被占用时，系统不得把第二个任务同时分配给它 |
| FR-304 | [Unwanted] 若无合格机器人，系统应将任务标记 FAILED 并记录原因，不得静默丢弃 |

### 3.4 安全运行时（FR-4xx）

| ID | 需求 |
|---|---|
| FR-401 | [Ubiquitous] 系统应在每个动作下发前执行电子围栏检查（禁入/停止/限速三类区） |
| FR-402 | [Unwanted] 若动作目标位于禁入区，系统应拒绝执行并中止任务（红线 R1） |
| FR-403 | [Event] 当停止区检测到人员时，系统应下发停机（speed_limit=0）并在人员离开、人工确认后恢复 |
| FR-404 | [Event] 当安全专员触发急停时，系统应立即抢占该机器人执行队列 |
| FR-405 | [Ubiquitous] 系统应将所有安全裁定（允许/拒绝/停机）连同红线编号写入证据链 |

### 3.5 执行与证据（FR-5xx）

| ID | 需求 |
|---|---|
| FR-501 | [Event] 当任务执行完成时，系统应自动挂载证据：trace + 遥测 + 技能版本（+ 快照类任务的快照） |
| FR-502 | [Unwanted] 若证据不完整，系统不得将任务标记 DONE（应打回重做） |
| FR-503 | [Ubiquitous] 系统应为每次执行生成可回放报告（trace_id 可重建全链） |
| FR-504 | [State] 当任务失败时，系统应按降级阶梯处置：L1 重试 → L2 规则兜底 → L3 遥操作 → L4 挂起 |
| FR-505 | [Ubiquitous] 系统应在降级发生时显式标记 `degraded=true` 与当前级数，不得静默降级 |

### 3.6 技能治理（FR-6xx）

| ID | 需求 |
|---|---|
| FR-601 | [Ubiquitous] 系统应将技能作为受控资产管理：版本化 + 四态（PENDING/APPROVED/REJECTED/SUPERSEDED） |
| FR-602 | [Event] 当新版本获批时，系统应自动将旧生效版本置为 SUPERSEDED |
| FR-603 | [Event] 当运维执行回滚时，系统应将指定版本恢复为 APPROVED 并记录操作 |
| FR-604 | [Unwanted] 若技能未经审批，系统不得在执行中引用它 |

### 3.7 数据飞轮（FR-7xx）

| ID | 需求 |
|---|---|
| FR-701 | [Event] 当任务完成时，系统应记录 episode（观测/动作/结果 + 技能与模型版本） |
| FR-702 | [Unwanted] 若 episode 缺数据授权单（consent_id），系统应拒绝入库 |
| FR-703 | [Ubiquitous] 系统应按"技能 × 成败"分片导出 JSONL，供训练场/数据服务消费 |
| FR-704 | [Ubiquitous] 系统应统计每技能成功率，作为技能迭代依据 |

### 3.8 对外接口（FR-8xx）

| ID | 需求 |
|---|---|
| FR-801 | [Ubiquitous] 系统应提供 REST API（/tg-api/v1）供业务系统集成 |
| FR-802 | [Ubiquitous] 系统应提供 MCP 服务端（/mcp）供智能体生态调用 |
| FR-803 | [Ubiquitous] 系统应按 robot_link.proto 提供机器人链路契约，adapter 可替换 |
| FR-804 | [Unwanted] 若外部请求参数非法，系统应返回 4xx 与可读错误，不得 500 |

## 4. 非功能需求

| ID | 需求 | 目标 |
|---|---|---|
| NFR-101 | 作业单提交到任务就绪 | P95 ≤ 2 s |
| NFR-102 | 单任务安全审查开销 | P95 ≤ 5 ms |
| NFR-103 | 证据完整率 | 100%（缺一即不得 DONE） |
| NFR-104 | 核心算法单测覆盖率 | ≥ 90%（现状 94%） |
| NFR-105 | 决策可解释率 | 100%（调度/安全/技能均有理由） |
| NFR-106 | 演示环境可用性 | 无真机全链路可跑（CI 门禁） |
| NFR-107 | 服务可用性目标 | 99.5%（单基地，双副本） |

## 5. 约束与假设

| # | 约束/假设 |
|---|---|
| C1 | 系统不向 PLC/DCS/SIS 下发控制指令（与 Diting-PdM 同纪律） |
| C2 | 首期机群为仿真 + 协议契约；真机适配按 adapter 后置 |
| C3 | VLA 技能由合作方/开源提供，平台只做治理与编排 |
| C4 | 厂区平面坐标为局部直角坐标（米），真机靠 UWB/二维码定位对齐 |
| C5 | 人工令牌由企业审批流（钉钉/企微）签发，平台提供登记入口 |
