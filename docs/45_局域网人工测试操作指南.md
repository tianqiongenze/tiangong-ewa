## 0. 五分钟准备

### 0.1 拿到两个地址

部署机上先查 IP（Windows `ipconfig`，Linux `ip addr`），得到形如 `192.168.1.50` 的地址：

| 用途 | 地址 | 说明 |
|---|---|---|
| **运营看板** | `http://192.168.1.50:8000/` | 服务同源托管，**浏览器直接打开** |
| **接口自检** | `http://192.168.1.50:8000/healthz` | 应返回 `{"status":"ok",...}` |

> 看板必须通过 `http://` 打开，**不要双击本地 `web/index.html`**（`file://` 会因跨域拿不到数据，
> 页面会显示"演示兜底"，容易被误判为故障）。

### 0.2 启动服务（部署机执行一次）

```bash
# Linux / macOS
cd impl/services/agent-runtime
TIANGONG_DB=/data/tiangong.db \
TIANGONG_BULK_DB=/data/tiangong_bulk.db \
TIANGONG_REDIS_URL=redis://127.0.0.1:6379/0 \
PYTHONPATH="../../packages/tiangong_core;." \
python -m granian --interface asgi app.server:app --host 0.0.0.0 --port 8000
```

```powershell
# Windows PowerShell（在 impl\services\agent-runtime 下）
$env:TIANGONG_DB="D:\tiangong\data\tiangong.db"
$env:TIANGONG_BULK_DB="D:\tiangong\data\tiangong_bulk.db"
$env:TIANGONG_REDIS_URL="redis://127.0.0.1:6379/0"
$env:PYTHONPATH="..\..\packages\tiangong_core;."
..\..\..\.venv\Scripts\python.exe -m granian --interface asgi app.server:app --host 0.0.0.0 --port 8000
```

**三个"必须"**：

1. `--host 0.0.0.0`（默认 `127.0.0.1` 只能本机访问，局域网打不开）；
2. `TIANGONG_DB` 必须指向文件（不设则是内存库，**重启数据全丢**）；
3. 缓存预热建议先跑一次 `python tools/warmup_cache.py`（否则首屏多等 1–2 秒）。

### 0.3 放行端口（Windows 最常见卡点）

```powershell
# 管理员 PowerShell，只需执行一次
New-NetFirewallRule -DisplayName "Tiangong 8000" -Direction Inbound `
  -Protocol TCP -LocalPort 8000 -Action Allow
```

Linux：`sudo firewall-cmd --add-port=8000/tcp --permanent && sudo firewall-cmd --reload`
（或 `ufw allow 8000/tcp`）。

### 0.4 打不开？按顺序试

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 本机能开、别人打不开 | 绑了 127.0.0.1 | 改 `--host 0.0.0.0` 重启 |
| 2 | 全部打不开 | 防火墙 | 执行 §0.3 |
| 3 | 浏览器转圈后失败 | 公司代理拦截内网 | 浏览器/系统代理里把 `192.168.*` 加入**直连例外** |
| 4 | `healthz` 通、看板空白 | 页面用了 `file://` | 用 `http://IP:8000/` 打开 |
| 5 | 看板显示"演示兜底" | 接口不可达 | 打开 F12 → Network 看 `/tg-api/v1/robots` 状态码 |
| 6 | 端口被占用 | 重复启动 | `netstat -ano \| findstr :8000` 找到 PID 后结束 |

## 1. 必测主链路（约 20 分钟）

> 每项都写清"看什么、正常是什么样、不对怎么记"。发现问题填 §5 的记录表。

### 1.1 首屏与数据源（2 分钟）

| 检查 | 正常表现 |
|---|---|
| 页面标题 | "天工 · 具身智能工厂作业智能体平台 / TIANGONG-EWA v1.1 运营看板" |
| 数据源徽标 | 右上角显示 **"数据源：实时 API"**（绿）；显示"演示兜底"（黄）即为异常 |
| KPI 卡 | 7 个数字均非 `—`；"分析库总行数"应为 100,000,000 量级（或你们导入的规模） |
| 控制台 | F12 → Console **无红色报错** |

### 1.2 机群遥测（2 分钟）

- 表格 4 行（AMR-01 / AMR-02 / ARM-01 / QD-01），电量为整数百分比，位置为 `x,y`
- 适配器表 3 行：`seer` / `mushadow` 显示"待联调"（dry-run，正常），`mock` 显示 `ok`
- 若显示 `down`：说明适配器真实不可用（未接 broker），记录并反馈

### 1.3 安全区地图（2 分钟）

- 地图上有 3 个区域：`Z-HV-ROOM`（禁入，红）、`Z-HUMAN-CROSS`（停止，红）、`Z-WALKWAY`（限速，黄虚框）
- 4 个机位圆点与右侧表格的坐标一致
- **重点**：禁入区与停止区必须是红色且位置正确（这是安全认知的一部分）

### 1.4 分析库概览（3 分钟）

| 字段 | 正常表现 |
|---|---|
| 总行数 | `100,000,000` |
| 库大小 | `5.03 GiB` 左右 |
| 7 天作业单 | 百万级（与数据规模成比例） |
| 查询耗时 | **个位数毫秒**（预聚合）；若显示上千毫秒，说明预聚合表缺失 |
| 缓存命中率 | 首次打开后刷新一次，应 > 60% |

### 1.5 下单 → 审批 → 执行（**核心闭环，5 分钟**）

1. 页面底部"下单 → 审批 → 执行"表单，保持默认（TRANSPORT，原料库→装配车间，35 kg，25,14）
2. 点 **提交作业单** → 出现 `WO-XXXXXXXX`，状态 `PENDING`
3. 点 **人工审批** → 状态变 `APPROVED`，审批按钮置灰
4. 点 **执行** → 状态变 `DONE`，"证据 N 条"应 ≥ 3
5. 回看上方"作业单看板"：该单出现在列表，任务数为 3

> 这一步走通，说明**业务闭环、审批闸门、证据链**三项都正常。

### 1.6 红线 R1：禁入区（3 分钟）

1. 目标坐标改成 `55` / `55`（高压配电房）
2. 提交 → 审批 → 执行
3. **预期**：状态 `ABORTED`，提示含 **"R1"** 与"禁入区"

> 若竟然执行成功，**立即停止测试并升级为 P1 安全事件**（红线被绕过）。

### 1.7 红线 R2：超载无令牌（3 分钟）

1. 重量改成 `80` kg（> 50 kg 阈值），坐标改回 `25` / `14`
2. 提交 → 审批 → 执行
3. **预期**：状态 `ABORTED`，提示含 **"R2"** 与"人工确认令牌"

## 3. 接口自检（3 分钟，技术侧）

浏览器直接访问以下地址，均应为 `200` 且有 JSON：

```
http://IP:8000/healthz
http://IP:8000/tg-api/v1/robots
http://IP:8000/tg-api/v1/zones
http://IP:8000/tg-api/v1/skills
http://IP:8000/tg-api/v1/observability/metrics
http://IP:8000/tg-api/v1/analytics/scale
http://IP:8000/tg-api/v1/analytics/summary?days=7
http://IP:8000/tg-api/v1/audit?limit=20
http://IP:8000/a2a/v1/card
```

**判读**：

- `analytics/summary` 里 `"source": "rollup"` 表示预聚合生效；`"raw"` 表示未建预聚合（性能会差 3 个数量级）
- `metrics.cache.l2_available` 为 `true` 说明 Redis 接上了；`false` 不影响功能，只是没有 L2

## 4. 异常与红线处置（现场必须知道）

| 情况 | 立即动作 |
|---|---|
| 机器人在动 / 人员进入停止区 | 点机器人行的急停（或调 `POST /robots/{id}/estop`），**先停再查** |
| 红线未拦截 | 停止测试、封存现场（截图 + 时间）、30 分钟内通知安全专员 |
| 数据明显不对（如 7 天单量 > 全库） | 停止采信看板数据，记录并反馈（可能是预聚合未更新） |
| 服务反复重启 | 查 `TIANGONG_DB` 是否指向了不可写目录 |

## 7. 与自动化测试的关系

| 层 | 谁做 | 覆盖 |
|---|---|---|
| 单元/接口（120 项） | 研发 CI | 领域规则、编排、缓存、分析口径 |
| 浏览器 E2E（13 项） | 研发 CI（`make e2e`） | 本指南 §1 的自动化等价物 |
| **人工验收（本指南）** | 客户/教师/学生 | 可理解性、多端体验、现场判断 |
| 压测（k6/Locust） | 性能专项 | 吞吐与延迟（docs/44） |

> 人工测试不是"重复劳动"：自动化证明"系统按设计工作"，
> 人工验收证明"人愿意用它、看得懂它、敢为它签字"。
