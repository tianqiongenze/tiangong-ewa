## 1. 数据总览：两类资产

```
┌────────────────────────────────────────────────────┐
│  受控资产：技能（Skill）—— 版本化、审批、灰度、回滚    │
├────────────────────────────────────────────────────┤
│  数据资产：episode —— 实景作业记录，脱敏 + 授权单      │
└────────────────────────────────────────────────────┘
```

2026 = 具身智能"数据元年"：实景任务数据是训练场与模型厂商的采购对象。
本项目把每次真实作业变成**带授权的训练数据**，形成数据飞轮。

## 2. 技能数据模型

```
Skill (skill_id, name, description)
  └── SkillVersion (skill_id, version, state, entry, canary_pct, approved_by)
        state ∈ {PENDING, APPROVED, REJECTED, SUPERSEDED}
```

规则：

1. 新版本初始 PENDING，必须审批
2. 同技能同时最多一个 APPROVED（生效版本 = version 最大者）
3. 新版本获批 → 旧生效版本自动 SUPERSEDED
4. 回滚 = 指定版本重新 APPROVED（不得回滚到 REJECTED）
5. 执行引用的技能版本必须写入证据链

## 3. episode 数据模型

```python
Episode(
  episode_id, task_id, robot_id,
  skill_id, skill_version, model_version,
  success, duration_s,
  observations: [...],   # 观测序列（脱敏）
  actions: [...],        # 动作序列
  outcome: {...},        # 结果
  consent_id             # 数据授权单（必填）
)
```

- `checksum`：SHA-256 前 16 位，防篡改校验
- `shard_key`：`{skill_id}/{'ok'|'fail'}`，按场景聚合
- 导出：JSONL，供训练场/数据服务消费

### 3.1 合规红线

| 规则 | 实现 |
|---|---|
| 无授权单不入库 | `EpisodeRecorder.record` 强制 consent_id |
| 厂内数据不出厂 | L3/L4 级数据（原始视频/波形）留基地，仅脱敏特征值上行 |
| 脱敏 | 采集前剥离人脸/工牌/商业秘密字段（adapter 层钩子） |
| 可审计 | checksum + consent_id + 版本号三元组 |

## 4. 数据流（飞轮）

```
真实作业 ──▶ episode 记录 ──▶ 分片（技能×成败）
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        技能迭代依据          模型训练数据         验收/复盘证据
     （成功率看板）        （导出给训练场）      （trace 回放）
```

指标：

- 每技能成功率（`success_rate`）→ 低于阈值触发技能迭代或降级权重
- episode 总量与分片分布 → 数据资产盘点
- 人工接管率（L3 触发频次）→ 自动化成熟度

## 5. 存储选型

| 环境 | 选型 | 理由 |
|---|---|---|
| 演示/CI | SQLite + 内存 | 零依赖，全链路可跑 |
| 生产（基地） | PostgreSQL + 对象存储 | 与 Diting-PdM 双后端同构；episode 落对象存储 |
| 生产（总部） | 数据湖（Parquet on S3） | 分片导出直接可用 |

## 6. 与 Diting-PdM 数据体系的关系

| Diting-PdM | 天工 | 联动 |
|---|---|---|
| 设备健康指数 HI / 告警 | 作业单触发器 | "HI 劣化 → 自动生成巡检作业单" |
| 工单/备件 | 作业结果回写 | "机器人完成 → 工单闭环" |
| 判据版本化 | 技能版本化 | 同一治理哲学 |

**合体愿景**：谛听负责"该修了"，天工负责"去修/去查"——预测性维护 × 具身执行的全闭环。
