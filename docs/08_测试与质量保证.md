## 3. 混沌与降级验证

```bash
make demo -- --chaos    # 全部机器人注入失败 → 验证 L1→L4 逐级下降
make demo -- --person   # 停止区有人 → 验证 R4 停机
```

每迭代至少执行一次（宪法第四条：降级路径必须被测试覆盖）。

## 4. 质量门禁（CI）

```yaml
ruff check packages services        # 静态检查
pytest -q --maxfail=1               # 全量测试
coverage report --fail-under=80     # 覆盖率门禁
python tools/demo_run.py            # 演示冒烟（无硬件）
buf lint contracts/proto            # 契约 lint
```

## 5. 缺陷分级与响应

| 级 | 定义 | 响应 |
|---|---|---|
| S1 安全 | 红线可被绕过/停机失效 | 停止发布 + 立即修复 + 复盘 |
| S2 功能 | 主链路断裂 | 当迭代修复 |
| S3 一般 | 非主链路缺陷 | 排期 |
| S4 体验 | 文案/提示 | 累积 |

## 6. DoD（Definition of Done）

一条任务"完成"的判据（与运行时的 DONE 判据对齐）：

1. 有规格（spec ID）
2. 有测试（覆盖新增分支）
3. 有证据（trace/遥测/技能版本）
4. 过门禁（CI 全绿）
5. 可回放（trace_id 重建）
6. 文档同步（受影响文档已更新）

> "能跑"不是完成；"能回滚、能观测、能解释"才是完成。
